# Engineering Math Standards — معايير الرياضيات الهندسية

> ملف تكميلي يُقرأ مع `.skills/solver-engine.md` (الفصل المعماري) و `.skills/vitest-testing.md` (اختبارات الدقة).

## 1) ثابت الـ 60fps (60fps Invariant)
- كل مسار حسابي مرتبط بالعرض (simulation ticks، رسوم متحركة، قراءات حية) يجب أن يبقى ضمن ميزانية الإطار الواحد: **أقل من 16.6ms** لكل frame على الأجهزة المستهدفة.
- الحسابات الثقيلة غير المرتبطة بالإطار: نفّذها خارج مسار العرض، جزّئها، أو انقلها إلى Web Worker عند تجاوز الميزانية.
- **ممنوع** وضع حلقات ثقيلة أو عمليات `Math` كثيفة داخل `render` أو داخل event handlers متكررة (mousemove/scroll).

## 2) الاستقرار العددي (Numerical Stability)
- تجنّب القسمة على قيم قريبة من الصفر؛ أضف guards صريحة وموثقة.
- راقب حالات `NaN` / `Infinity` وامنع تسرّبها إلى طبقة العرض.
- استخدم صيغاً مستقرة عددياً عند الحاجة (مثل الجمع التعويضي Kahan)، وانتبه لترتيب العمليات العددية (جمع الصغير قبل الكبير عند الحساسية).
- الحلقات التكرارية (تكامل، محاكاة زمنية، تقارب): حدّد حداً أقصى لعدد الخطوات + معيار تقارب tolerance معلن.

## 3) عدم المساواة العائمة (No Float Equality)
- **ممنوع** `===` / `==` على القيم العشرية. استخدم دائماً:
```ts
const EPS = 1e-9; // قيمة موثقة ومبررة حسب سياق الحساب
if (Math.abs(v1 - v2) < EPS) { /* ... */ }
```
- وثّق قيمة الـ tolerance وتعليلها في كل محرك (١e-9 للهندسة العامة، أعلى للتكامل/التقارب).
- تفضيل دالة مقارنة موحدة في المحركات (`isClose(a, b, eps)`) بدلاً من قيم مبعثرة.

## 4) حدود التعقيد (Complexity Bounds)
- المسارات الساخنة (لكل frame أو لكل تغيير إدخال) يجب أن تكون $O(N)$ أو أفضل — **ممنوع** $O(N^2)$ داخل الـ frame loop.
- عند الحاجة لفحص زوجي (pairwise): استخدم spatial hashing، أو بنية بيانات مقصودة، مع تبرير مكتوب في تعليق.
- **قس ولا تخمّن:** أي تفاعل يتجاوز 16ms يجب تبسيطه تعقيدياً قبل إضافة الميزة.

## 5) تنسيق KaTeX
- العرض الأكاديمي (القيم، المتغيرات، المصفوفات، الوحدات) **فقط** عبر KaTeX (`react-katex`).
- لا تكشف LaTeX خاماً أو معرفات UUID داخلية للمتعلم.
- لا تخلط نصاً عادياً ومعادلة رياضية في سطر واحد دون فصل واضح.
- الصيغة المعروضة يجب أن تمثل المنطق الحقيقي للمحرك — **لا معادلات تجميلية بلا معنى حسابي**.

## 6) بوابات الجودة الرياضية (Math Quality Gates)
- [ ] كل دالة رياضية: مدخلات/مخرجات موثقة + نطاق صلاحية معلن
- [ ] كل مقارنة رقمية عبر tolerance معلن ومبرر
- [ ] حالات حدية مختبَرة: صفر، قرب-صفر، سالب، قيم قصوى
- [ ] لا `NaN` / `Infinity` يتسرب للعرض
- [ ] المسار الساخن $O(N)$ ومقاس (< 16.6ms)
- [ ] اختبار Vitest يثبت الدقة بعدد المنازل المطلوب
- [ ] قيم الإدخال تتحقق قبل الحساب (حسب `solver-engine.md` §5)
