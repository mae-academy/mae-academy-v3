# Solver Engine Standards

## 1) الهدف
المحرك الحسابي يجب أن يكون طبقة مستقلة عن React وUI. هدفه هو:
- حساب النتائج بدقة،
- تبسيط المنطق الرياضي،
- تمكين الاختبارات بسهولة،
- الحفاظ على قابلية إعادة الاستخدام عبر واجهات متعددة.

## 2) مبادئ التصميم
### 2.1 فصل المحرك عن الواجهة
- لا تعتمد الدوال الحسابية على React state أو DOM أو hooks.
- لا تكتب كوداً يحسب النتائج داخل مكونات UI مباشرة إذا كان يمكن عزله إلى دوال مُستقلة.
- إذا كان هناك منطق فيزيائي/هندسي/رياضي، فضعه في ملف أو وحدة مخصصة للمحرك.

### 2.2 نقاء الدوال
- اجعل الدوال pure whenever possible.
- الإدخال -> خرج واضح، بدون تأثيرات جانبية.
- Avoid mutation of shared objects unless clearly required and documented.
- استخدم قيم إرجاع صريحة، لا تعتمد على state خارجي.

### 2.3 التوثيق
- كل محرك أو دالة رياضية تحتاج إلى شرح موجز لما يضيفه، ما المدخلات، وما المخرجات.
- إذا كان هناك تفسير أو فرضية رياضية مهمة، وثّقها قرب الكود أو في مستندات المشروع.

## 3) الحسابات العلمية
- التزم بالدقة والتمثيل الرقمي الصحيح.
- استخدم tolerances عند مقارنة النتائج أو فحص الاستقرار.
- إذا كان هناك عدم استقرار أو تقارب، وثّق هذا الظرف في التعليقات أو الاختبارات.
- تجنب الحسابات الغامضة أو التلاعب العددي غير المبرر.

## 4) هيكل المشروع
الأفضل أن يكون هناك فصل واضح بين:
- UI: عرض وتفاعل
- Hooks: ربط UI مع المحرك
- Engines / Solvers: الحسابات الأساسية
- Shared / Utils: وظائف مساعدة مشتركة
- Tests: التحقق من الدقة والسلوك

## 5) التعامل مع الإدخال
- لا تعتمد على القيم المجهولة أو state الخارجي داخل المحرك.
- التحقق من أنواع المدخلات قبل الحساب.
- إذا كانت قيمة الإدخال غير صالحة، أعد رسالة أو قيمة واضحة ومفهومة.

## 6) الأداء والقدرة على التوسع
- تجنب الحسابات المتكررة غير الضرورية.
- استخدم تقنيات مناسبة مثل memoization أو المعالجة المجمعة إذا كانت الكفاءة مطلوبة.
- حافظ على محرك الحسابات قابلاً للتوسعة لكل حالة جديدة أو معيار جديد.

## 7) اختبار المحرك
- اختبر المدخلات الأساسية، الحواف، القيم الحرجة، والنتائج المتوقعة.
- اختبر أن هناك دقة كافية عند مقارنة النتائج.
- عند اكتشاف خطأ في الحساب، لا تفسره كـ UI issue قبل التحقق من المحرك نفسه.

## 8) النتيجة المطلوبة
المحرك الحسابي يجب أن يكون:
- مستقلاً عن React,
- قابل للاختبار،
- دقيق،
- قابل للقراءة،
- مهيأ لتمثيل نموذج حقيقي بدلاً من مجرد كود متحكم في الواجهة.

## 9) قاعدة التنفيذ
عندما تقوم ببناء أو تعديل محرك:
1. حدّد المدخلات والمخرجات بوضوح.
2. أبقِ الحسابات نقية قدر الإمكان.
3. افصل بين المنطق والواجهة.
4. اجعل الاختبار يثبت أن النتيجة صحيحة.
5. لا تخلط بين العرض والتفسير والرياضيات.
