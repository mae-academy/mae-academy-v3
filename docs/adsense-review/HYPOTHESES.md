"Low value content" decisions; Google does not publish per-site reasons beyond the Policy Center message, and that

| # | Hypothesis | Result | Evidence |
|---|---|---|---|
| H1 | Content pages use hash-based routing | **REJECTED** | wouter path routing (`client/src/App.tsx:16,89-123`); no `HashRouter`/`useHashLocation`/`#/` links in `client/src`. The only fragment is the in-page anchor `#data-deletion` (`PrivacyPolicy.tsx:60`). |
| H2 | Raw HTML has almost no readable text on simulator pages | **CONFIRMED (before) → FIXED for 33 routes** | Before: every route, including all simulators, returned the same 62-word body, same title, no canonical (`evidence/raw-html-results.md`, 1 unique sha256 across `/`, `/simulations/control-systems/pid`, `/about`, `/privacy`). | H3 | robots.txt or firewall blocks render resources from Googlebot | **REJECTED (repo) / UNTESTABLE (edge)** | robots.txt: Googlebot, Mediapartners-Google and AdsBot-Google have their own groups with empty `Disallow:`; the `*` group's `Disallow: /api/` does not apply to them. `/assets/` JS/CSS are allowed for all. No firewall/bot rules in the repo (`vercel.json` has headers/redirects/rewrites only). Vercel Firewall / Bot Protection / Cloudflare settings live in dashboards → NEEDS OWNER (I-3). |
| H4 | Library pages are mostly external embeds without original text | **CONFIRMED** | Entries come from Internet Archive / Open Library / DOAB at runtime (`client/src/lib/*.ts`); reader is PDF.js over `/api/pdf-proxy` (`RestrictedPdfViewer.tsx:55`); no commentary fields exist in code or data. | H5 | Language switching produces no separate URL, or redirects by Accept-Language | **CONFIRMED (no separate URL); REJECTED (Accept-Language redirect)** | Language stored in `localStorage["mae-locale"]` (`i18n/config.ts:58-65`, `main.tsx:10`). `/ar`, `/es` → 404 before and after. No hreflang. No Accept-Language handling anywhere (`lng: 'en'` fixed default). Google advises against relying on cookies/browser settings to choose the language of a single URL (https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites, *not re-fetched*). Consequence: Arabic/Spanish content is effectively invisible to crawlers. |
| H6 | Bot protection challenges special-crawler IP ranges | **UNTESTABLE** | No firewall, WAF, rate-limit-by-IP or bot rules for HTML in the repo. The `api/_lib/security` rate limiter applies to `/api/*` POST engines only. The live site and the official IP list (https://developers.google.com/crawling/docs/crawlers-fetchers/google-special-case-crawlers, *not re-fetched*; host blocked this session) could not be reached. **Owner must check** Vercel Firewall/Bot Protection/Attack Challenge Mode (or Cloudflare) logs for requests from Mediapartners-Google and for challenge (403/429/JS challenge) responses (I-3). |
| H7 | Simulator pages lack original explanatory text | **REJECTED as stated, with a provenance caveat** | Every simulator tool has 567–1075 English prose words (Arabic 495–928) with theory, captioned equations, control mapping and a worked example (CONTENT-AUDIT §1). But before C-1 none of it was in raw HTML, and all of it was added in one AI-co-authored commit (`79dcb36`) with a uniform template. Whether it is owner-reviewed is unknown → O-1. |
| H8 | Short math notes are templated | **REJECTED — the notes do not exist** | No research-note data, route or component exists; `/research` is an OpenAlex/DOAB search UI. The home page advertises "Open research notes … algorithmic proofs … validated against benchmark experiments" (`landing.json:48`) and an "Explore Research Notes" CTA. Advertising content that is not there is a content-accuracy issue → O-6. |
