## Part 1 — engine fixes

### 1. PDF + code execution (HTTP 400) — fixed and verified

- **Root cause, reproduced directly against Gemini** (`gemini-3.6-flash`, one-page PDF):
  `PDF + codeExecution` → **HTTP 400** `The mime type: application/pdf is not supported for code execution.`; the same PDF without the tool → **HTTP 200**.
- **Fix** (`server/aiService.ts`, `codeExecutionEnabled(env, request)`): `codeExecution` is omitted whenever the request carries a PDF (the active document or any message attachment). Plain-text turns keep the sandbox; `GEMINI_CODE_EXECUTION=0` still disables it everywhere.
- **Verified:** the live PDF case (a generated 2-question mechatronics exam) returns HTTP 200 with both answers (4 mA, 0.1 N·m) and clean KaTeX. Unit tests cover text vs PDF vs the env switch.
- Images are not restricted: the requirement named PDFs/document formats, and handwritten-work turns keep the sandbox.

### 2. Model fallback cascade — implemented, with one deliberate deviation

- Every request starts on `gemini-3.7-flash`. If it fails on **every key** (429 after the 2 s / 4 s per-minute backoff, 503/500/504, or 404 "model unavailable"), the request steps down the list, each tier again rotating the whole key pool, with no error shown.
- **Deviation from the requested list.** The requested tiers `gemini-2.5-flash`, `gemini-2.0-flash` and `gemini-1.5-flash` are **retired for these keys** (HTTP 404 "no longer available to new users"), so a cascade made only of them could never answer. The default is now
  `gemini-3.7-flash → gemini-3.6-flash → gemini-3.5-flash → gemini-2.5-flash → gemini-2.0-flash → gemini-1.5-flash`.
  Retired tiers cost one 404 and are skipped; they stay in the list in case a key still serves them. Override with `GEMINI_FALLBACK_MODELS=a,b,c` (comma list, `off` disables).
- If every tier fails, the **preferred model's** error is reported (so a quota problem still shows the proper rate-limit message).
- **Two extra failure modes found by the audit and fixed:**
  1. A connection that opens and then breaks **before the first chunk** (SDK error `Incomplete JSON segment at the end`) used to surface as HTTP 502. Opening the stream and reading its first chunk is now one cascade step, so it steps down like an overloaded model. (Robotics failed with 502 twice before this.)
  2. A connection that drops **mid-answer** produced "MAE AI stopped unexpectedly". The stream now resumes: it re-asks the model to continue from the text already shown (max 2 resumes). A first attempt that simply treated the partial frame as "complete" truncated a reply inside a code block, so it was replaced by the resume. Observed twice in the final run; both replies passed all checks.
- **Behavior observed in this run:** `gemini-3.7-flash` returned 429 on all 7 keys for every request (daily per-project quota, partly consumed by this audit's own calls), so **all 7 answers came from `gemini-3.6-flash`**. The cascade never needed to go below tier 2. The per-request key-rotation and fallback lines are in the live report.

### 3. Upload limits — verified

- Server: `/api/ai/chat` uses `express.json({ limit: "72mb" })`. Live probe: a **70 MB** body is accepted by the size limit (it reaches validation and gets HTTP 400 because the probe is deliberately not a real chat), a **74 MB** body gets **HTTP 413**. No 413 below the cap.
- Client: `AI_MAX_PDF_BYTES = 50 * 1024 * 1024`, enforced in `documentUtils.ts` (12 tests pass).
